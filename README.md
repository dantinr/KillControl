# Kill Control

Kill Control 是一款面向 Windows 的应用卸载、残留复核、后台服务管理、资源、网络和程序行为监控工具，使用 Visual Studio 2026、.NET 10 和 WPF 开发。程序文件仍使用 `Kill.exe`，产品名称为 **Kill Control**；当前版本号由仓库根目录的 `VERSION` 文件统一管理，并显示在程序主界面和窗口标题中。

## 合并版 1.2.17

Kill Control 与行为哨兵 ProcessSentinel 现已合并。主窗口统一提供“应用管理 / 服务管理 / 开机启动 / 资源监控 / 网络监控 / 行为监控 / 隔离记录”，监控直接内嵌在本程序中。切换页面保留监控会话，顶部提供监控状态与停止全部监控；关闭程序时等待后台采集、日志保存及管理操作完成。

顶部菜单栏中，“隔离记录”后面的“关于”显示产品版本、功能简介、项目地址与许可证信息。

便携包仅需启动 `Kill.exe` 或对应版本化入口。`ProcessSentinel.Collector.exe` 是按需提权的内部采集组件，请保留整个发布目录。原始 `processSentinel` 仓库与其已发布版本未修改。

行为监控支持四个程序并发、完整进程树、文件/网络/注册表/模块记录、按进程出网统计、独立风险复核和日志导出。设置和日志目录兼容原版，详见 [行为监控说明](docs/BEHAVIOR_MONITOR.md)。

## 核心功能

### 应用管理

- 从 32/64 位、当前用户和所有用户卸载注册表项读取桌面应用。
- 读取当前用户可卸载的 MSIX/AppX 商店应用。
- 应用列表和详情显示运行状态与关联进程数，页面可见时每 3 秒刷新；悬停可查看 PID 和进程路径。
- 运行状态依据登记安装路径或图标中的可执行文件匹配；缺少路径或共用路径无法归属时显示“无法判断”，“未检测到”不代表能排除所有受权限限制的后台进程。
- 优先运行应用登记的官方卸载程序，不模拟或替代厂商卸载流程。
- 支持选择安装目录，通过登记位置、显示图标和官方卸载器路径反向识别应用后运行官方卸载。
- 多个应用命中同一目录或只命中深层子目录时，该目录只用于识别，不会作为整体残留清理。
- 扫描可与应用名称明确对应的安装目录、AppData、ProgramData 和注册表残留。
- 清理前逐项复核；高风险项目默认不选中，并要求输入应用名称确认。
- 默认将文件移入隔离区并导出注册表备份，支持查看隔离记录和恢复。
- 支持不可恢复的“直接清理”，执行前会再次给出高风险提示。

### 服务管理

- 默认列出正在运行且宿主可明确归为第三方软件的服务。
- 支持搜索服务名称、发布者、服务命令和宿主路径。
- 支持查看服务状态、启动方式、运行账户、进程 ID、宿主程序和服务模块。
- 支持定位宿主、禁止运行、列入/移出黑名单，以及备份配置后删除服务。
- Windows、Microsoft、驱动、关键服务和宿主来源不明确的服务会进入“系统保护”，只能查看和定位。
- 所有服务修改均通过 Windows UAC 提权，并在提权工作进程中重新读取和复核服务信息。

可从主窗口进入“服务管理”，也可以直接运行：

```powershell
.\Kill.exe --services
```

### 开机启动

- 查看当前用户、所有用户的 Run 注册项（含 HKLM 32/64 位视图）及 Windows 启动文件夹中的文件，按名称、命令、状态和用户范围筛选。
- 详情显示原始命令、来源位置和范围，支持定位文件、禁用和恢复。禁用不终止程序，恢复不立即运行程序，均影响后续登录。
- 禁用前保存原始注册值及类型，或保留原始启动文件；恢复拒绝覆盖同名项目。当前用户备份在 `%LOCALAPPDATA%\Kill\StartupBackups`，所有用户备份在管理员保护的 `%ProgramData%\KillStartupBackups`。
- 修改所有用户项目时按需 UAC 提权，工作进程验证同一用户身份并重新读取原项、检查内容与权限。Windows 路径的注册项、路径无法确认的注册项、隐藏/系统启动文件仅查看。
- “已注册”表示条目存在，不保证应用一定启动。Windows StartupApproved 状态仅作只读提示，未知格式显示“状态待确认”；Windows 已禁用项可通过页面右上角的系统设置入口调整，不写入未公开的状态格式。
- 不包含 RunOnce、计划任务、服务及商店应用启动任务；服务仍在“服务管理”中调整。支持 `Kill.exe --startup` 直接打开。

Windows 启动来源参见 [Microsoft 启动应用说明](https://support.microsoft.com/en-us/windows/experience/startup-boot/configure-startup-applications-in-windows) 与 [Run 注册项文档](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)。

### 资源监控

- 可组合选择 CPU、物理内存、硬盘 I/O 和网络吞吐量。
- 支持 5 秒、30 秒、1 分钟、3 分钟和 5 分钟采样间隔。
- 支持不限时、30 分钟和 60 分钟监控时长；达到时长后自动结束并保存会话。
- 当前值与最近 200 条记录显示在监控窗口中，完整历史保存在本地 SQLite 数据库。
- 趋势统计显示最近 120 个样本的 CPU、内存、硬盘读写和网络收发曲线，并在启动时恢复本地历史记录。
- 进程 Top 10 可按 CPU 使用率、工作集或进程 I/O 吞吐量排序；排名显示最后采样时间，随监控采样刷新，不写入历史数据库。
- Top 10 的 I/O 来自 Windows 进程 I/O 计数器，不等同于单个进程的网络吞吐量；网络曲线仍是系统总量。
- 监控仅在资源监控窗口打开并点击“开始监控”后运行，不安装后台服务，也不在程序退出后继续采样。
- 支持清空全部历史监控数据；该操作需要输入“清空”二次确认。

可从主窗口进入“资源监控”，也可以直接运行：

```powershell
.\Kill.exe --resources
```

### 网络监控

- 独立展示全机 TCP/UDP、IPv4/IPv6 连接与监听/绑定端点，显示进程名、PID、本地/远端 IP 和端口、连接状态。
- 每秒更新发送/接收速率、本次累计发送/接收字节、连接首次发现后的观测时长，以及全局汇总和监听数。
- 可按进程、PID、路径、IP 或端口搜索，筛选 TCP/UDP，隐藏已结束记录，按流量或速率数值排序；选中行查看完整路径、地址及首次发现时间。
- 右键连接列表中的进程行，可选择“打开程序目录”；进程路径无法读取或目录不存在时，该操作不可用。
- 点击“开始监控”才通过 Windows UAC 启动独立管理员采集器；主界面保持普通权限。切换页面持续采集，停止或关闭主窗口会结束采集。
- 流量仅统计本次启动后收到的 ETW 传输事件，包含本机及局域网，并非运营商计费流量；不读取数据包内容。UDP 没有固定连接，发生传输后按远端分别显示。
- 已存在连接的真实建立时间不可追溯，因此显示“观测时长”。实时统计重新开始会重置；实时列表最多保留 5,000 行，截断或事件丢失在底栏显示，累计总量仍继续统计。
- “连接历史”按进程实例保存远端 IP、端口、协议、首次/最后观测时间及累计收发；停止、重新开始或退出后仍可查看。选中实时连接再打开历史可定位对应进程，支持按进程名/PID/路径和远端 IP/端口搜索、分页。
- 历史保存在 `<程序目录>\data\network-history.db`，仅包含启用网络监控后收到的连接快照，不追溯启动前记录；监听和没有远端的 UDP 绑定不计入历史。

可直接运行 `Kill.exe --network` 打开面板。数据来源、边界和开发验证方法见 [网络监控说明](docs/NETWORK_MONITOR.md)。

## 安全边界

不存在能够对任意 Windows 软件保证“完美卸载、零残留、零影响”的通用算法。便携软件、未登记的软件、其他 Windows 用户的商店包，以及多个程序共用的组件，都无法可靠地自动归属。

Kill Control 因此采用保守策略：

- 不做模糊名称匹配，不递归搜索整块磁盘。
- 不清理 Windows、Common Files、WindowsApps、磁盘根目录或常见共享目录。
- 无法明确归属的文件、目录、注册表项和服务宁可保留。
- 服务删除前必须导出注册表配置；建议优先选择“禁止运行”。
- 如果服务拒绝立即停止，Kill Control 会明确提示禁用状态将在重启后生效。
- 黑名单会记录原启动方式并禁用服务，但不是常驻拦截器；拥有管理员权限的软件仍可重新创建或修改自己的服务。

## 数据目录

| 内容 | 默认位置 |
| --- | --- |
| 临时提权请求 | `%LOCALAPPDATA%\Kill\Temp` |
| 隔离记录 | `%ProgramData%\Kill\History` |
| 系统盘隔离文件 | `%ProgramData%\Kill\Quarantine` |
| 服务注册表备份 | `%ProgramData%\Kill\ServiceBackups` |
| 服务黑名单 | `%ProgramData%\Kill\ServiceBlacklist.json` |
| 资源监控数据库 | `<程序目录>\data\kill-monitor.db` |
| 进程网络连接历史 | `<程序目录>\data\network-history.db` |
| 其他磁盘隔离文件 | `<磁盘根目录>\Kill Quarantine` |

恢复操作不会覆盖原位置已经存在的内容。清理请求/响应、操作标识、历史清单及隔离副本均由提权工作进程重新校验；恢复注册表时只允许导入原键范围内的备份，并保留已经存在的键。其他磁盘使用同卷隔离目录，避免跨卷移动造成额外复制或中断风险。

## 开发与构建

在 Visual Studio 2026 中打开 `Kill.slnx`，将 `Kill` 设置为启动项目，选择 `Debug | Any CPU` 后按 `F5`。

Release 构建：

```powershell
dotnet build .\Kill.slnx -c Release
```

编译结果统一写入仓库根目录的 `Releases\`。其中保留稳定入口 `Kill.exe`，并额外生成 `Kill-v<版本号>.exe`；Debug 构建仍使用项目默认的 `bin\Debug\`。普通 Build 生成的两个 EXE 都依赖 `Releases\` 中当前的 `Kill.dll` 和运行配置，需要独立保存历史版本时，应使用下面的单文件发布产物。

检查代码格式：

```powershell
dotnet format .\Kill.slnx --verify-no-changes --verbosity minimal
```

运行只读安全自检：

```powershell
dotnet run --project .\Kill.SelfTest\Kill.SelfTest.csproj -c Release
```

生成自包含的 Windows x64 合并版便携包（包括内部采集器）：

```powershell
.\build.ps1 -Package
```

脚本先检查格式、构建、运行两套自检和统一界面回归，再发布到 `Releases\Kill-portable-win-x64-v<VERSION>\` 并生成同名 ZIP。主程序和采集器分别为自包含单文件，固定使用 .NET/WPF 10.0.11，主程序保留 `Kill.exe` 与哈希一致的版本化入口，同时携带许可和使用说明。每个产品版本使用独立目录。

只构建并验证可执行 `build.ps1`。现有隔离、服务记录及行为设置保留原位置；资源历史仍位于 `<程序目录>\data\kill-monitor.db`。换到新版本目录时，如需沿用资源历史，请在原程序关闭后手动复制 `data` 目录，避免覆盖新目录已有数据。

`Releases/`、`artifacts/`、`bin/`、`obj/` 和 Visual Studio 用户文件已由 `.gitignore` 排除。

直接运行 `Releases\Kill.exe` 时，资源监控数据库位于 `Releases\data\`。清理构建目录前，如需保留历史监控记录，应先备份该目录。

## 版本管理

`VERSION` 只保存一行 `x.x.xx` 格式的版本号，末段从 `10` 开始并限制在 `10` 到 `99`。末段超过 `99` 时，中间段进位并将末段重置为 `10`，例如 `1.2.99` 的下一版本是 `1.3.10`。构建会校验格式，并把同一个值写入程序集、Windows 文件属性及发布目录中的 `VERSION` 文件。
