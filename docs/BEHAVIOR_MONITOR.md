# Kill Control 行为监控

行为监控已从 ProcessSentinel 迁入 Kill Control，与应用管理、服务管理、资源监控、隔离记录共用同一个主窗口和产品版本。

## 使用

1. 打开“行为监控”，选择运行中的进程，点击“添加监控”。允许 Windows 提升内部采集器的权限；主界面仍按当前用户权限运行。
2. 默认监控所属程序的完整进程树。选择子进程也会识别相关父进程、兄弟和子孙；公共启动器、系统宿主和 Kill Control 本身是追溯边界。取消勾选后只监控所选 PID。
3. 可同时监控四个程序，每个会话独立保留行为、进程名单、完整日志和复核记录。也可选择 EXE，从挂起启动阶段开始监控。
4. 在“行为记录”“监控进程”“需要复核”间切换，查看完整路径和触发原因。普通列表保留最近 5,000 条；复核记录独立保留，导出包含当前会话的全部已保存记录。
5. 切换到应用、服务或资源页面会保留正在运行的监控。顶部显示监控状态，并提供“停止全部监控”。退出主程序会等待采集停止、日志保存和正在进行的管理操作完成。

“工具 → 设置”管理默认程序树范围、风险筛选和日志目录。保留原 `%LOCALAPPDATA%\ProcessSentinel\settings.json` 与 `%LOCALAPPDATA%\ProcessSentinel\Sessions`，已有设置和磁盘日志不会迁移或删除。旧日志格式可继续用于读取和导出；界面当前会话在退出后不自动恢复。

## 数据口径

- ETW 记录文件操作请求、TCP/UDP 端点与传输字节、注册表操作、子进程、模块加载。文件操作请求不代表成功，不读取文件、注册表值或 HTTPS 内容。
- 进程“出网流量”只累计本进程自开始监控发送到公网的字节，不含接收、局域网、本机通信；代理和服务代发活动可能不能归属。
- 资源监控的进程 I/O 是 Windows 进程 I/O 计数，系统网络曲线是系统总量，与行为监控的进程出网量分别展示。
- “需复核 / 高关注”是行为线索，不代表确认恶意。风险提示不会自动卸载、隔离文件或修改服务。
- ETW 或队列丢失会显示计数。监控仅在手动开始后运行，不安装常驻服务。UAC 必须使用同一 Windows 账户。

## 开发验证

`build.ps1` 运行管理自检、行为自检和绑定真实 WPF 控件的界面回归。`build.ps1 -Package` 额外生成版本化便携目录和 ZIP。

真实采集诊断使用 `Kill.exe --verify-collector <报告路径> <ProcessSentinel.SelfTest.exe 路径>`，仅监控自行创建的临时文件测试目标，采集器会请求 UAC。诊断不卸载软件、不操作真实服务、不写注册表；资源数据库和行为日志使用独立临时目录。该检查与普通界面回放分开记录。
